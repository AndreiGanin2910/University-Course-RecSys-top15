# 🎓 University Course Recommendation System

> Гибридная рекомендательная система для выбора дополнительных университетских курсов: история студента, семантика описаний, обучаемая совместимость и ансамбль градиентного бустинга.

Проект по реальным обезличенным данным **Московского городского педагогического университета (МГПУ)**.

**Лучший результат на лидерборде — `0.4528070` по pNDCG@5.** В репозитории собран рецепт этого решения с обучением из исходных данных.

---

## 🎯 Описание задачи

Каждый семестр студент выбирает дополнительные курсы и расставляет приоритеты. По предыдущим выборам, профилю студента и описаниям дисциплин нужно рекомендовать **пять доступных курсов** на следующий период.

У задачи есть несколько особенностей:

| Особенность | Как учитывается в решении |
|---|---|
| Каталог меняется между периодами | Обучение учитывает доступность курсов; для новых курсов используются контентные признаки |
| У части студентов нет истории | Отдельная смесь избранного и прошлой популярности |
| Порядок реальных выборов важен | Вес положительного примера зависит от приоритета |
| Описания содержат счётчик избранного | Он извлекается в отдельный сигнал и удаляется из текста для E5 |
| Метрика насыщается после достаточного попадания | Порядок холодной пятёрки оптимизируется по ожидаемой capped DCG |

### Данные

| Файл | Содержимое | Размер |
|---|---|---:|
| `train.jsonl` | Профили и истории первых двух периодов | 5 002 студента |
| `val.jsonl` | Студенты третьего периода и доступная история | 3 043 студента |
| `val_solution.csv` | Известные выборы третьего периода с приоритетами | 3 043 ответа |
| `test.jsonl` | Студенты четвёртого периода | 4 306 студентов |
| `modules.jsonl` | Названия, описания и периоды доступности курсов | 322 курса |

В тестовом периоде доступны **158 курсов**. У **2 790 студентов** есть история, у **1 516** её нет. Числа относятся к исходной версии датасета соревнования.

## 🏗 Архитектура решения

```text
             Исходные данные P1–P3 и каталог курсов
                              │
             ┌────────────────┼────────────────┐
             ▼                ▼                ▼
     История и профиль    Тексты курсов    Популярность,
        студента          TF-IDF / E5     избранное, соседи
             └────────────────┼────────────────┘
                              ▼
                  116 базовых признаков
                              │
             ┌────────────────┴─────────────────┐
             ▼                                  ▼
      E5-совместимость                 Ridge по истории
      история ↔ кандидат               с семантическим ядром
             │                                  │
             └───────────── crossfit ────────────┘
                              ▼
                   LightGBM + CatBoost
                              ▼
           Выравнивание распределений прогнозов по курсам
                              ▼
          Ранговая смесь + поправка для новых курсов
                              ▼
             Отдельная холодная пятёрка и её порядок
                              ▼
                        submission.csv
```

Код организован в одном `main.py`: настройки → признаки → модели → смесь → запись рекомендаций. Функции сгруппированы по этапам пайплайна.

### 1. Базовые признаки

Для каждой пары «студент — доступный курс» формируются **116 численных признаков**.

| Блок | Количество | Примеры сигналов |
|---|---:|---|
| Профиль, статистики и контент | 35 | Популярность курса, предпочтения института и специальности, совпадения названий, прошлые выборы |
| Семантика E5 | 8 | Сходство с историей, перенос предпочтений на семантически близкие курсы |
| Темы и языки | 53 | Тематические теги, языковые интересы, совпадения курса с историей и профилем |
| Соседи по истории | 20 | Голоса 50/200 похожих студентов, приоритетные выборы, семантический перенос соседских голосов |

Исторические признаки используют только периоды, предшествующие целевому. При расчёте соседских признаков собственный голос студента исключается.

### 2. Обучаемая E5-совместимость

Тексты кодируются замороженной моделью **`intfloat/multilingual-e5-large`**. Вход — название и описание с префиксом `query: `. Служебный текст с числом добавлений в избранное предварительно удаляется.

Все **1 024 координаты** эмбеддинга используются для построения модели совместимости:

- эмбеддинги центрируются и нормируются;
- история студента агрегируется с учётом приоритетов и давности;
- две обучаемые линейные проекции переводят историю и кандидата в пространство размерности **64**;
- модель учит сходство и отдельный коэффициент повторного выбора курса.

Это обучаемая проекция, а не предварительное PCA/SVD. Основные параметры: **80 эпох**, `learning_rate=0.002`, `weight_decay=0.05`, `dropout=0.1`, `seed=42004`.

Прогнозы используются как прямая поправка ансамбля и как **четыре дополнительных признака** деревьев. Для обучающих строк эти признаки рассчитываются через crossfit.

### 3. Ridge по истории

Вход Ridge объединяет последний семестр, более ранние выборы и профиль студента. Семантическое ядро связывает похожие курсы:

```text
K = (I + 0.5 × V × Vᵀ) / 1.5
```

Здесь `V` — центрированные нормированные E5-векторы. Регуляризация Ridge — **10**. Если курс отсутствовал в каталоге периода, этот период не используется как источник отрицательных примеров для соответствующего выхода Ridge.

Прогноз Ridge используется напрямую и в виде **двух дополнительных признаков CatBoost**. Обучающие признаки также получаются через crossfit.

### 4. Градиентный бустинг

| Компонент | Основные параметры | Назначение |
|---|---|---|
| Базовые LightGBM | 600 деревьев, 31 лист, `lr=0.035`, `min_child_samples=200` | Исходный контентный и приоритетный сигнал |
| Расширенные LightGBM | 1 800 деревьев, 63 листа, `lr=0.035`, `min_child_samples=50` | Более полные признаки и E5-совместимость |
| CatBoost | 1 000 итераций, глубина 7, `lr=0.06`, `l2_leaf_reg=10` | Категории, E5 и Ridge |

В CatBoost передаются категории `module_id`, `institute`, `specialty`. Пропуски профиля заменяются на `_missing_`. ID студента в качестве признака не используется.

Деревья решают задачу бинарной классификации выбора курса. В приоритетных моделях вес положительного примера умножается на `priority_weight / 0.65`. Примеры P3 получают дополнительный вес **1.5**.

### 5. Финальная смесь

Основные настройки вынесены в начало `main.py`:

| Настройка | Значение |
|---|---:|
| Приоритетная модель внутри LightGBM-ветки | 75% |
| Смесь исходной и расширенной LightGBM-веток | 50 / 50 |
| Прямая поправка E5 | 25% |
| Прямая поправка Ridge | 25% |
| Финальные ранги LightGBM / CatBoost | 75 / 25 |
| Бонус ранга избранного | 0.05 |

Перед смешиванием E5/Ridge-прогнозы выравниваются по распределению оценок каждого курса. Это позволяет использовать персональный порядок эксперта, сохраняя исходный масштаб популярности курса.

Для новых курсов действует отдельная ветка: контентные прогнозы и ограниченная поправка по избранному. Настройки поправки — сила **0.5**, предел изменения шансов **4**, сглаживание **10**. Избранное рассматривается как эвристический сигнал интереса, а не как известный будущий выбор.

### 6. Студенты без истории

Холодная пятёрка выбирается по смеси рангов:

```text
cold_score = 0.8 × rank(favorites) + 0.2 × rank(previous_popularity)
```

Первые два места сохраняются. Для оставшихся трёх перебираются все перестановки. Их ожидаемая полезность оценивается по совместным выборам P3, перевзвешенным под смесь текущего избранного и прошлой популярности.

Так постобработка учитывает насыщение метрики и совместные попадания. Список вычисляется из данных; конкретные ID курсов в код не зашиты.

## 📏 Метрика

Используется официальный **pNDCG@5** из `metric.py`:

```text
gain(priority): 1 → 1.00, 2 → 0.80, 3 → 0.60, 4 → 0.45, 5 → 0.35

pNDCG@5(student) = min(1, Σ gain(true_priority(course_at_rank)) / log₂(rank + 1))
Score = mean(pNDCG@5(student))
```

Курс, которого нет среди реальных выборов, даёт нулевой вклад. В этой метрике нормировка равна одному: её нельзя заменять стандартной NDCG с делением на DCG всей идеальной пятёрки.

## 📐 Схема обучения и валидации

```text
P1 → P2             обучающие примеры из train.jsonl
P1–P2 → P3          локальная разработка и проверка гипотез
P1–P3 → P4          финальное обучение и рекомендации для test.jsonl
```

Во время разработки использовались два трёхфолдовых разбиения P3 и дополнительная временная проверка: обучение на P2, оценка на P3. Для признаков обучаемых моделей применялись вложенные разбиения, исключающие ответы проверяемого студента.

В финальном обучении известные ответы P3 разрешены: они относятся к прошлому относительно P4. `main.py` обучает именно финальный рецепт. Для честной локальной оценки всего ансамбля требуется отдельный внешний цикл фолдов; сравнивать его обучающие прогнозы с `val_solution.csv` нельзя.

Метрику для заранее полученного отложенного прогноза можно проверить так:

```bash
python metric.py --solution data/val_solution.csv --submission val_submission.csv
```

`val_submission.csv` в этой команде — отдельный честный прогноз P3. Финальный `main.py` создаёт `submission.csv` для P4.

## 🚀 Быстрый старт

Рекомендуется **Python 3.11** и отдельное окружение.

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Для Windows окружение активируется командой `.venv\Scripts\activate`.

Положите пять исходных файлов соревнования в `data/`, затем запустите:

```bash
python main.py
```

Пути `DATA_DIR` и `OUTPUT_NAME` задаются в начале `main.py`. По умолчанию путь данных считается относительно самого скрипта, поэтому запускать его можно из другой рабочей папки.

При первом запуске скачиваются веса E5 из Hugging Face. Зафиксирована ревизия модели:

```text
3d7cfbdacd47fdda877c5cd8a79fbcc4f2a574f3
```

Пайплайн рассчитан на CPU. Нужно учитывать память для E5-large, матриц пар «студент — курс» и вложенного обучения. Время зависит от CPU, числа потоков и скорости загрузки модели; фиксированное время запуска не заявляется.

### Формат результата

После выполнения рядом с `main.py` появится `submission.csv`:

```csv
id,recommendations
student_example,course_a course_b course_c course_d course_e
```

Это условный пример формата. Каждая реальная строка содержит ID из теста и пять разных доступных курсов без указания приоритетов, в порядке рекомендации.

### Воспроизводимость

Код перенесён из самостоятельного ноутбука лучшего решения. Для E5 зафиксированы ревизия и seed, для обучающих разбиений и моделей сохранены исходные настройки. Решение читает исходные данные и веса E5; сохранённые прогнозы прошлых экспериментов ему не нужны.

При подготовке этой версии проверены соответствие вычислительных функций исходному ноутбуку, формирование 116 признаков на примерах P2/P3 и финальная сборка на сохранённых прогнозах. Сборка восстановила все **4 306 строк** лучшего сабмита, включая 1 516 холодных; SHA256 CSV совпал с зафиксированным хешем отправленной версии. Сохранённые прогнозы использовались только для этой внешней проверки и не входят в зависимости `main.py`.

Полное обучение публикационной сборки заново не запускалось. Результат `0.4528070` относится к отправленному в соревнование файлу; побитовое совпадение после переобучения в новой среде не заявляется.

Список зависимостей фиксирует версии для запуска, но не является полным lock-файлом всех транзитивных пакетов. Численные результаты могут зависеть от библиотек и CPU.
